# OpsBot — Additional Supported Queries
**FEATURE-1 | Date:** 2026-06-18

Three additional chat queries supported beyond the 5 core PBI scenarios. All retrieve live data from PostgreSQL via the MCP server.

---

## 1. Risk prediction for a specific elevator

**Example prompts:**
- "What is the risk level of elevator 10234?"
- "What is the risk level of elevator 88712?"
- "Show me the risk level for elevator 45001"

> **Classifier note:** The phrase "risk level" (weight 1.0) + extracted elevator ID (entity bonus 0.5) reaches the 0.6 confidence floor. Shorter phrasings like "Is elevator X high risk?" score 0.5 and fall back to advisory. Use "risk level" in the prompt.

**MCP tool:** `get_elevator_risk`
**Intent trigger:** `data_query` + keyword `"risk"` + extracted elevator ID

**What it returns:**
The ML risk prediction for the elevator: risk level (LOW / MEDIUM / HIGH), risk score, and the plain-language explanation generated by `generate_explanations.py`. If no prediction exists for the elevator (only the top 500 highest-risk devices are scored), the tool returns a `"message"` field stating no prediction is available — OpsBot will tell the user to treat the device as unclassified.

## 2. Fleet-wide statistics

**Example prompts:**
- "How many elevators are at each risk level?"
- "List elevators by risk level"
- "Which elevators have which risk level?"

**MCP tool:** `get_fleet_stats`
**Intent trigger:** `data_query` with no specific sub-keyword match (default fallback)

> **Classifier note:** The phrase "risk level" (weight 1.0) + a second keyword like "how many" or "list" (0.5 each) reaches the 0.6 confidence floor without an elevator ID, routing to the default case → `get_fleet_stats`. Generic prompts like "Give me a fleet summary" have no matching keywords and fall back to advisory.

**What it returns:**
Three aggregate values from three separate queries:
- Risk distribution — count of elevators by risk level (HIGH / MEDIUM / LOW / UNKNOWN)
- Inspection pass rate — percentage of most-recent inspections that passed
- Total active elevators in the fleet

This mirrors the summary cards shown on the operations dashboard.

## 3. Full-text search over incident narratives

**Example prompts:**
- "Find incidents mentioning door malfunction"
- "Are there any incidents involving entrapment?"
- "Search incident reports for hydraulic failure"

**MCP tool:** `search_incident_narratives`
**Intent trigger:** `data_query` with keyword `"incident"` and no specific elevator ID — if the query sounds like a keyword search rather than a count

> **Note:** The current intent classifier routes generic incident queries without an ID to `get_incident_count_last_year`. To reach `search_incident_narratives` directly, the user message should contain specific search terms (e.g., "find incidents mentioning X" or "search incident reports for Y"). The classifier will be refined in a future sprint to distinguish count vs. narrative-search intent.

**What it returns:**
Up to 20 incidents whose narrative text matches the query using PostgreSQL full-text search (`plainto_tsquery`). Each result includes the incident ID, date, category, injury severity, and a highlighted excerpt (`ts_headline`) showing the matched terms.
